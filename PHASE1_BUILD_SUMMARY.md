## Database Schema Updates

### New Models Added to `prisma/schema.prisma`

#### **Tier 4: Predictive Analytics & ML**

1. **MLModel**
   - Fields: id, name, type, version, accuracy, lastTrained, status, createdAt, updatedAt
   - Purpose: Store ML model metadata and configuration
   - Statuses: pending, training, active, archived
   - Relations: Has many Predictions

2. **Prediction**
   - Fields: id, modelId, targetId, targetType, prediction, confidence, reasoning, createdAt
   - Purpose: Store predictions generated by ML models
   - Indexes: modelId, targetType
   - Relations: Belongs to MLModel

3. **CustomReport**
   - Fields: id, name, description, metrics[], filters, schedule, recipients[], lastGenerated, createdById, createdAt, updatedAt
   - Purpose: Enable users to create custom reports with scheduled delivery
   - Schedules: null, 'daily', 'weekly', 'monthly'
   - Relations: Belongs to User (creator)

#### **Tier 5: Ecosystem Integration**

1. **Integration**
   - Fields: id, service, apiKey, apiSecret, webhookUrl, status, config, lastSync, createdAt, updatedAt
   - Purpose: Manage third-party service integrations
   - Services: 'salesforce', 'stripe', 'mailchimp', 'twilio', etc.
   - Statuses: connected, disconnected, error
   - Unique: One integration per service

2. **IntegrationLog**
   - Fields: id, service, action, status, payload, response, error, createdAt
   - Purpose: Track all integration API calls and webhook events
   - Actions: 'sync', 'webhook', 'api_call'
   - Statuses: pending, success, failed
   - Indexes: service, status

#### **Tier 8: Security & Compliance**

1. **TwoFactorAuth**
   - Fields: id, userId, secret, backupCodes[], enabled, createdAt
   - Purpose: Store TOTP-based 2FA configuration
   - Relations: One per User (unique constraint)
   - Encryption: secret and backupCodes stored encrypted

2. **SecurityAuditLog** (renamed from AuditLog for Tier 8)
   - Fields: id, userId, action, resource, resourceId, status, ipAddress, userAgent, metadata, createdAt
   - Purpose: Track security-relevant actions (login, export, data_access, delete)
   - Actions: 'login', 'export', 'data_access', 'delete'
   - Statuses: 'success', 'failed'
   - Indexes: userId, action, createdAt

3. **DataRetentionPolicy**
   - Fields: id, dataType, retentionDays, autoDelete, lastPurged, createdAt, updatedAt
   - Purpose: Define data retention periods for compliance
   - Default retention: 90 days
   - Unique: One policy per data type

4. **GDPRRequest**
   - Fields: id, userId, type, status, fileUrl, completedAt, createdAt
   - Purpose: Track GDPR data requests (export, delete, rectify)
   - Statuses: pending, processing, completed, failed
   - Relations: Belongs to User

#### **Tier 13: Performance & Infrastructure**

1. **PerformanceMetric**
   - Fields: id, page, metric, value, unit, device, timestamp
   - Purpose: Track Core Web Vitals and performance metrics
   - Metrics: 'LCP', 'FID', 'CLS', 'TTFB'
   - Devices: 'mobile', 'tablet', 'desktop'
   - Indexes: page, metric, timestamp

2. **CacheEntry**
   - Fields: id, key, value, ttl, hits, lastAccessed, createdAt, expiresAt
   - Purpose: Manage application caching layer
   - Unique: key (for quick lookups)
   - Tracks: Hit count and last access time for analytics

### User Model Relations Added

```prisma
customReports       CustomReport[]
securityAuditLogs   SecurityAuditLog[]      @relation("SecurityAuditLogs")
twoFactorAuth       TwoFactorAuth?
gdprRequests        GDPRRequest[]   @relation("GDPRRequests")
```

## API Routes Created

### 1. Predictions Endpoint
**Path:** `/app/api/enrichment/predictions/route.ts`

**Methods:**
- `GET` - Fetch predictions with filters (modelId, targetType)
- `POST` - Create new prediction

**Features:**
- Pagination support (limit parameter)
- Model information included in response
- Filtering by model and target type

**Response Format:**
```json
{
  "success": true,
  "data": [...],
  "count": number
}
```

- Backup codes generation (10 codes)
